JavaScript 공부 노트

이 페이지의 코드 상자는 실제로 실행된다. 페이지를 열면 자동으로 실행된 결과가 아래에 나오고, ▶ 다시 실행 버튼으로 다시 돌려볼 수 있다. 맨 아래 놀이터에서 직접 코드를 써볼 수도 있다.

1. JavaScript의 역할

언어역할비유 (인스타 클론)
HTML정보와 구조프로필 사진, 이름, 게시물이 "있다"
CSS모양 (디자인)사진이 동그랗고, 3열로 배치된다
JavaScript동작 (프로그래밍)좋아요를 누르면 하트가 채워지고, 숫자가 올라간다

웹브라우저가 직접 실행해주는 유일한 프로그래밍 언어다. 별도 설치 없이 브라우저만 있으면 된다.
이름이 비슷한 Java와는 완전히 다른 언어다. (C와 C++처럼 가까운 사이도 아니다)

HTML에 JavaScript 넣는 방법

<!-- 1. 문서 안에 직접 -->
<script>
    console.log("Hello");
</script>

<!-- 2. 외부 파일 연결 (CSS 의 link 와 비슷) -->
<script src="./js/main.js"></script>

<script> 태그는 보통 <body> 맨 끝에 둔다. 위쪽 HTML이 먼저 만들어져야 JavaScript가 그 요소들을 찾아서 다룰 수 있기 때문이다. (이 페이지도 맨 끝에 있다)

2. 실행 방법 : 브라우저 개발자 도구 > 콘솔 (인터프리터)

브라우저에서 F12 → Console(콘솔) 탭을 열고 코드를 치고 Enter를 누르면 바로 실행된다.

C / C++ (컴파일러 방식)JavaScript (인터프리터 방식)
실행 과정소스 작성 → 컴파일 → 실행 파일(.exe) 생성 → 실행코드를 쓰면 그 자리에서 바로 실행
번역 시점실행 전에 전체를 한 번에 번역실행하면서 한 줄씩 번역
오류 발견컴파일 단계에서 미리 많이 잡힘그 줄을 실행해 봐야 알게 됨
장점빠른 실행 속도고치고 바로 확인 (시험하기 편함)

이해하신 대로다. 참고로 요즘 브라우저의 JavaScript 엔진(Chrome의 V8)은 내부적으로 속도를 위해 일부를 컴파일(JIT)하기도 하지만, 개발자 입장에서는 컴파일 과정 없이 바로 실행되는 언어로 쓰면 된다.

콘솔에서 자주 쓰는 것

JavaScript
console.log("Hello, JavaScript!")    // 출력 (C 의 printf, C++ 의 cout)
console.log(1 + 2)
console.log("3" + 4)                 // 문자열 + 숫자 = 문자열 (뒤에서 다시 나옴)
console.log("a", 1, true)            // 여러 개를 쉼표로 한 번에

콘솔에 직접 입력하면 마지막 식의 값이 자동으로 출력되지만(1 + 2 만 쳐도 3이 나옴), 파일 / script 태그 안에서는 console.log()를 써야 출력된다. 그래서 이 노트의 예제는 모두 console.log를 쓴다.

4. 문자열 메서드 : . 으로 호출하기

C++의 str.length(), C#의 str.ToUpper()처럼 값 뒤에 .을 찍고 기능(메서드)을 호출한다. 메서드가 새 값을 돌려주기 때문에 그 뒤에 .을 또 이어서 쓰는 메서드 체이닝도 가능하다.

JavaScript
let s = "Hello, JavaScript"
console.log(s.length)               // 17   ← 괄호가 없다! (메서드가 아니라 속성)
console.log(s.indexOf("Java"))      // 7    (찾은 위치, 없으면 -1)
console.log(s.indexOf("xyz"))       // -1
console.log(s.includes("Script"))   // true (포함 여부)
console.log(s.toUpperCase())        // 대문자로
console.log(s.toLowerCase())
console.log(s.slice(0, 5))          // 0번부터 5번 앞까지 잘라내기
console.log(s.replace("Hello", "Bye"))
console.log("ab".repeat(3))         // 반복
console.log("a,b,c".split(","))     // 쪼개서 배열로
console.log("  hi  ".trim())        // 앞뒤 공백 제거
console.log(s)                      // 원본은 그대로! (새 값을 돌려줄 뿐)

// 메서드 체이닝 : 결과에 바로 . 을 이어 씀
console.log("  hello  ".trim().toUpperCase().repeat(2))
메서드 / 속성하는 일
length글자 수 (속성이라 괄호 없음)
indexOf("x")처음 나오는 위치 (없으면 -1)
includes("x")포함하는지 true / false
slice(시작, 끝)일부 잘라내기 (끝은 미포함)
split("구분자")쪼개서 배열로
replace("a", "b")바꾸기 (처음 하나만. 전부는 replaceAll)
toUpperCase() / toLowerCase()대문자 / 소문자
trim()앞뒤 공백 제거
repeat(n)n번 반복
startsWith("x") / endsWith("x")시작 / 끝이 같은지

문자열은 수정할 수 없는 값(immutable)이다. 메서드는 원본을 바꾸는 게 아니라 새 문자열을 만들어 돌려준다. (C++ std::string과 다른 점)

JavaScript

거짓(falsy) 6가지 암기 : false 0 "" null undefined NaN
"의미 없는 값 = 거짓, 내용이 있는 값 = 참"으로 기억하면 된다. 단 "false"나 "0"은 글자가 있으므로 참이다.

5-4. 자동 변환 (주의!)

JavaScript는 타입이 다른 값끼리 연산하면 알아서 변환해 버린다. 편하지만 놀라운 결과가 나오기도 한다.

JavaScript
console.log("3" + 1)      // "31"  : + 는 문자열이 하나라도 있으면 이어붙이기
console.log("3" - 1)      // 2     : - * / 는 숫자로 바꿔서 계산
console.log("3" * "4")    // 12
console.log(true + 1)     // 2

입력창에서 받은 값은 항상 문자열이다. 계산 전에 Number()로 바꾸지 않으면 "3" + "4"가 "34"가 되는 실수가 자주 생긴다.

6. 인덱싱 : [ ]

JavaScript
let s = "hello"
console.log(s[0])                // h  (0부터 시작, C 와 같음)

7. 변수 : let, const

JavaScript
let count = 0            // let : 값을 바꿀 수 있는 변수 (타입을 안 쓴다)
count++                  // 증가 (-- 도 가능)
count += 5               // 복합 대입 (-= *= /= 도 가능)
console.log(count)       // 6
count--
console.log(count)       // 5

let x = 1
x = "이제 문자열"          // 같은 변수에 다른 타입도 넣을 수 있음 (동적 타이핑)
console.log(x)

const PI = 3.14          // const : 한 번 정하면 바꿀 수 없음 (C 의 const 와 비슷)
try {
    PI = 3
} catch (e) {
    console.log(e.name + ": " + e.message)   // 바꾸려 하면 에러
}
키워드재대입설명
let가능값이 바뀌는 변수
const불가값이 안 바뀌는 변수. 기본은 const, 바뀔 때만 let을 쓰는 것이 요즘 관례
var가능옛날 방식. 범위 규칙이 달라 헷갈려서 쓰지 않는다 (옛날 코드에서 보면 let으로 읽으면 됨)
C / C++과 다른 점
· 세미콜론 ;은 줄 끝에 생략할 수 있다. (쓰는 코드도 많으니 둘 다 읽을 줄 알면 된다)
· 타입을 쓰지 않는다. 값이 들어갈 때 타입이 정해지고 바뀔 수도 있다.
· 변수 이름은 myAge처럼 camelCase(첫 단어 소문자, 다음 단어 대문자 시작)를 쓰는 것이 관례다.
· const 객체 / 배열은 안의 내용은 바꿀 수 있다 (변수가 가리키는 대상만 못 바꿈).

== 와 === 의 차이 (매우 중요)

JavaScript
console.log(3 == "3")             // true   : == 는 타입을 맞춰서 비교 (자동 변환)
console.log(3 === "3")            // false  : === 는 타입까지 같아야 true
console.log(0 == "")              // true   (!)
console.log(0 === "")             // false
console.log(null == undefined)    // true
console.log(null === undefined)   // false
console.log(3 !== "3")            // true   : !== 는 === 의 반대

항상 ===, !==를 쓴다. ==는 자동 변환 때문에 예상 밖의 결과가 나온다. AI가 쓴 코드도 대부분 ===를 쓴다.

12. <script>로 JavaScript 넣기 : 스스로 작동 (사용자 상호작용 없음)

브라우저는 HTML을 위에서 아래로 읽다가 <script>를 만나면 그 자리에서 JavaScript를 실행한다. 사용자가 아무것도 누르지 않아도 페이지가 열리면 저절로 한 번 실행된다.

12-1. 페이지가 열릴 때 스스로 HTML을 채우기

<p id="todayDemo"></p>                  <!-- 비어 있는 p -->

<script>
    const today = new Date()                 // 지금 날짜와 시간
    const p = document.getElementById("todayDemo")
    p.textContent = "오늘은 " + today.toLocaleDateString("ko-KR") + " 입니다"
</script>

HTML에는 빈 <p>만 있는데, 페이지가 열리자마자 JavaScript가 날짜를 채워 넣었다. 새로고침할 때마다 코드가 다시 실행된다.

12-4. 외부 파일로 분리하기 + 실행 시점

실행 시점이 중요한 이유 : 브라우저는 위에서부터 읽기 때문에, <script>가 대상 요소보다 위에 있으면 그 요소가 아직 없어서 찾지 못한다. (그래서 보통 <body> 맨 끝에 두거나 defer를 쓴다)

JavaScript
// 없는 요소(또는 아직 안 만들어진 요소)를 찾으면 null 이 나온다
const el = document.getElementById("없는-id")
console.log(el)

// null 에 대고 속성을 쓰려고 하면 에러 → 가장 흔한 에러 중 하나
try {
    el.textContent = "안녕"
} catch (e) {
    console.log(e.name + ": " + e.message)
}
에러 메시지 읽는 법 : Cannot set properties of null / Cannot read properties of null이 보이면 "요소를 못 찾았다"는 뜻이다. id 오타이거나 script 위치가 요소보다 위인지 먼저 확인한다.

인라인 이벤트 모델의 평가 (12_1_3.html 의 정리) : 가성비가 좋다. 코드가 짧고 빠르게 만들 수 있다. 하지만 HTML이 정보의 뼈대만이 아니라 "기능"까지 포함하게 된다 (HTML=구조, JS=동작으로 나누는 원칙이 무너짐). 그래서 작은 연습이나 테스트에는 좋지만, 커지는 프로젝트에서는 표준 이벤트 모델(addEventListener)로 분리한다.

13-2. 방법 2 : JS에서 요소의 속성에 대입 (요소.onclick = 함수)

HTML과 JS가 분리되어 깔끔하지만, 한 이벤트에 핸들러를 하나만 둘 수 있다. 나중에 대입한 것이 앞의 것을 덮어쓴다.

2. 요소 속성 대입고전 이벤트 모델btn.onclick = 함수하나 (덮어씀)분리는 되지만 덮어쓰기 주의
3. addEventListener표준 이벤트 모델btn.addEventListener("click", 함수)여러 개 가능권장. 현대 코드는 대부분 이 방식

e.key 비교는 대소문자를 구분한다. e.key === "q"는 소문자 q일 때만 참이고, Shift나 CapsLock을 켠 "Q"는 거짓이다. 둘 다 잡으려면 e.key.toLowerCase() === "q"로 쓴다. 키의 물리적 위치로 구분하려면 e.code("KeyQ")를 쓸 수 있다.

자주 하는 실수
1. btn.addEventListener("click", sayHi()) : 괄호를 붙이면 지금 바로 호출되고, 그 결과가 핸들러로 등록되어 버린다. 함수 자체를 넘겨야 한다 : addEventListener("click", sayHi)
2. 이벤트 이름에는 on을 붙이지 않는다 : addEventListener("click", ...) (O) / "onclick" (X). on이 붙는 것은 방법 1, 2의 속성 이름이다.
3. script가 요소보다 위에 있어서 null을 얻는 경우 (12-4)
4. 입력창의 value는 항상 문자열이다. 계산하려면 Number(input.value) (5번)
5. HTML 주석은 -->로 닫아야 한다. <!-- ... >처럼 >만 쓰면 주석이 안 닫혀서 그 뒤의 모든 내용이 주석이 된다. (12_2_5.html 맨 아래 주석)
6. 속성 이름 onClick / onclick : HTML은 대소문자를 구분하지 않아 둘 다 동작하지만, 소문자 onclick으로 쓰는 것이 관례다. (JS의 btn.onclick은 반드시 소문자)
7. <script>를 </body> 뒤에 쓰면 브라우저가 알아서 body 안으로 옮겨줘서 동작은 하지만 올바른 HTML은 아니다. </body> 바로 앞에 둔다.

14. DOM 조작 : JavaScript로 HTML 요소 바꾸기

12번에서 getElementById, textContent를, 13번에서 addEventListener를 이미 썼다. 이것들을 합쳐서 인스타 클론의 좋아요 버튼을 만드는 기본 형태를 정리한다.

14-1. HTML 요소 찾기 : getElementById 와 querySelector (12_1_3, 12_2_5)

document 객체 = 현재 HTML 문서 전체를 나타내는 객체다. "문서를 제어하기 위한 것"으로, 요소를 찾고 바꾸는 모든 작업이 document.에서 시작한다. (12_1_3.html 의 주석)

document.querySelector("선택자")는 CSS 선택자(3번, 26번)를 그대로 써서 요소를 찾는다. getElementById보다 훨씬 다양하게 찾을 수 있어서 요즘 가장 많이 쓴다.

메서드찾는 것못 찾으면
getElementById("id")id가 같은 요소 하나 (선택자 아님, # 안 붙임)null
querySelector("선택자")선택자에 맞는 첫 번째 요소 하나null
querySelectorAll("선택자")맞는 모든 요소 (목록)빈 목록 (길이 0)
JavaScript (이 페이지에서 실제로 찾아봅니다)
console.log(document.querySelector("h1").textContent)           // 태그 선택자
console.log(document.querySelector("#likeBtn").id)             // id 선택자 (# 를 붙임!)
console.log(document.querySelector(".like-box") !== null)      // class 선택자 (. 를 붙임!)
console.log(document.querySelector("input[type='text']").id)   // 속성 선택자 : 첫 번째 text 입력창
console.log(document.querySelector("#없는id"))                  // 못 찾으면 null
console.log(document.querySelectorAll(".demo-js").length)      // 코드 실행 상자의 개수
console.log(document.querySelectorAll("#없는id").length)        // 못 찾아도 에러가 아니라 길이 0
// 12_1_3.html : 속성 선택자 두 개를 연결해서 정확히 그 버튼만 찾기
document.querySelector("input[type='button'][value='click1']")

// 12_2_5.html : 입력창 찾기
document.querySelector("input[type='text']")

변수에 담을 때는 무엇인지 알 수 있는 이름을 쓴다. 12_2_5.html 에서 텍스트 입력창을 button2로 이름 지었는데, 이러면 읽을 때 헷갈린다 → textInput처럼 쓴다. 바뀌지 않는 값이므로 let 대신 const를 쓰는 것이 관례다.

14-3. 좋아요 버튼 만들기

<button id="likeBtn">🤍 좋아요 0</button>

<script>
    let likes = 0
    const btn = document.getElementById("likeBtn")      // 1. HTML 요소를 id 로 찾는다

    btn.addEventListener("click", () => {               // 2. 클릭되면 아래 함수를 실행해라
        likes++
        btn.textContent = "❤️ 좋아요 " + likes            // 3. 글자 바꾸기
        btn.classList.add("liked")                       // 4. CSS 클래스 추가 (색 변경)
    })
</script>
← 직접 눌러 보세요 (위 코드가 실제로 동작 중)
